# PBR2GTA 0.2.8 × Sollumz 2.8.0

2026-09-15. Диагностика и смоки; исправление в аддон не внесено. Пользовательская установка Sollumz и рабочая сцена не изменялись.

## Вывод

Ошибка со скриншота воспроизведена на официальном Sollumz 2.8.0: `Converting py args to operator properties:: keyword "target_formats" unrecognized`.

В 2.8.0 оператор содержит `custom_settings: PointerProperty(type=ExportSettingsOverride)`. Параметры `target_formats`, `target_versions`, `limit_to_selected` находятся внутри этой группы. PBR2GTA 0.2.8 возобновляет экспорт с параметрами верхнего уровня, как в проверенной 2.9. Интерфейс конвертации работает, поэтому проблема выглядит как внезапная ошибка после успешного превью.

README заявляет Sollumz 2.9+, но `bridge.compatibility_error()` проверяет только наличие свойств материала и оператора. Несовместимая структура оператора заранее не выявляется.

## Среда и положительный контроль

- Официальный [Sollumz 2.8.0](https://github.com/Sollumz/Sollumz/releases/tag/v2.8.0), SHA-256 ZIP: `75732b875e9bf9c72aca31e5763a47f10fbfdb04676b3b0fe73eb825b874542b`.
- Полный установленный PBR2GTA 0.2.8, SHA-256 ZIP: `4c902534f69a85763a7a588faac81b5ea744eed2bffb990f1d64924c7cbdbdb3`.
- Основной прогон: Blender 4.5.11 LTS, отдельный профиль, `szio==1.0.0`, `pymateria==0.1.0` для Python 3.11, внешний NVTT. Обе зависимости Sollumz подтвердил как доступные.
- Те же тестовые объекты успешно экспортировались штатным Sollumz с отключённым перехватчиком PBR2GTA: YDR и YDD, Native и CWXML, GEN8. Все четыре файла прочитаны обратно через szio.
- Версия Blender у получателя скриншота пока неизвестна. Это воспроизведение ошибки версии API, а не полная копия его окружения.

Legacy YDD прочитан обратно: значения 0.88, 0.37, 0.37, 0.63 соответствуют отключённому, общему и LOW-материалам. Два вхождения общего материала принадлежат разным Drawable внутри словаря.

Эти смоки проверяли числовой откат и отсутствие конечных файлов при отказе. Полная побайтовая проверка всех Blender datablock при отказе в этот прогон не входила.

## Другие разрывы поддержки 2.8

1. **Возобновление экспорта:** `ExportSession.export()` и `export_without_intercept()` отправляют плоские аргументы старому оператору. Это подтверждённая пользовательская ошибка.
2. **Сохранение индивидуальных настроек:** `_export_kwargs()` при `use_custom_settings=True` читает сам оператор, а не его `custom_settings`; `_selected_only()` тоже не читает вложенную группу. Проверка функций показала: запрошено `limit_to_selected=True`, в preferences стоит False → фактически получено False, захвачено только `use_custom_settings=True`. Это проверка функций на структуре старого API, а не успешный сквозной запуск custom-settings оператора.
3. **Папки и цели YTD:** `_write_sidecars()` при custom settings вызывает `to_export_context_settings()` на операторе. В 2.8 метод принадлежит вложенной группе. Проверка воспроизвела отсутствие метода. Простое удаление `target_formats` не исправляет поддержку полностью.
4. **Предварительная совместимость:** неподдерживаемая структура API пропускается к конвертации. Нужна проверка возможностей до worker с понятным сообщением.

Отдельное ограничение Sollumz: чистая установка 2.8.0 с его штатным PyMateria 0.1.0 не загрузилась в Store Blender 5.2.1 / Python 3.13. Установщик выбрал wheel `cp312-abi3`, внутри которого находится `_pymateria.cp312-win_amd64.pyd`; импорт завершился `No module named 'pymateria._pymateria'`. Для основного прогона использован настоящий cp311-wheel на Blender 4.5. Зависимости и бинарники не переименовывались. Это не причина уже воспроизведённой ошибки `target_formats`; окружение получателя нужно рассматривать отдельно.

## Причинный эксперимент

Только в памяти тестового Blender временно заменена передача параметров: сохранённые значения помещались в preferences 2.8, оператор вызывался с `use_custom_settings=False`, затем preferences восстанавливались через `finally`.

При этом YDR и YDD успешно экспортировались в Native/XML вместе с YTD и DDS. Все файлы прочитаны обратно; калибровка соответствовала отдельным материалам, отключённый материал сохранился, preferences восстановлены. DDS: 512×512, BC1/BC3/BC5U, 8 mip-уровней до 4×4.

Эксперимент подтверждает локализацию проблемы в передаче настроек. Это не готовое исправление: он не реализует полноценное сохранение индивидуальных nested settings и не проверяет всю матрицу 2.8/2.9. Исходники установленного аддона не менялись; подмена функции восстановлена.

## Что исправлять

Нужен общий адаптер настроек экспорта, распознающий фактические RNA-свойства: плоские в 2.9 и вложенные в 2.8. Один источник эффективных настроек должен использоваться для выбранных объектов, сессии, возобновления экспорта и YTD. Legacy-путь сохраняется. Перед worker следует проверять совместимость; после исправления повторить штатный экспорт на обеих версиях, включая индивидуальные настройки, смену выделения и отказ с откатом.

До такого исправления проверенный обход для 2.8 — legacy CodeWalker XML. Поддержку обычного Native-экспорта PBR2GTA на 2.8 сейчас обещать нельзя.
