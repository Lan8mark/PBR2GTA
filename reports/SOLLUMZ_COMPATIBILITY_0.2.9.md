## Исправленные разрывы совместимости

### Параметры материала больше не зависят от экспорта

При включённом **Use PBR2GTA** калиброванные value params поддерживаются непосредственно в материале. Изменение Surface действует сразу. Ручное изменение контролируемого значения исправляется после обновления сцены. После выключения PBR2GTA текущие значения остаются и доступны для ручного редактирования.

Обработчики повторно синхронизируют материалы после Undo, Redo и загрузки файла. Сравнение учитывает точность float32, чтобы не создавать постоянный цикл обновлений. Повреждённый обязательный узел вызывает понятное сообщение; материал автоматически не перестраивается.

**Автоматическая конвертация PNG и создание YTD при экспорте сохранены.** Перехват экспорта остаётся для подготовки текстур и атомарной записи комплекта, но больше не применяет калибровочный patch из worker.

### Повторный запуск экспорта учитывает возможности API

Адаптер выбирает настройки из Preferences, `custom_settings` либо самого оператора. Набор переносимых полей определяется схемой настроек установленного Sollumz. Служебные поля Blender вроде `bl_idname` и `directory` туда не попадают.

Повторный запуск использует зарегистрированный оператор с общими аргументами, временно подставленными Preferences и отключённым custom-режимом, если такой переключатель существует. Он не передаёт `target_formats` как неподдерживаемый аргумент оператора 2.8.0. Пользовательские параметры из окна экспорта предварительно сохраняются; после операции Preferences восстанавливаются.

В 2.8.3 и 2.9.0 Sollumz собирает выделение через `view_layer.objects.selected`. Одного `context.temp_override(selected_objects=...)` недостаточно. Поэтому адаптер временно выделяет исходные корни и затем восстанавливает актуальное выделение пользователя, активный объект и затронутые флаги видимости.

### Старый Sollumz работает без szio

Ветка 2.7 использует собственный каталог шейдеров и XML-экспорт. Справочник и YTD теперь получают определения через установленный Sollumz и не требуют отсутствующий в нём szio. Учтено поведение старых XML-классов, возвращающих `None` для неизвестных атрибутов.

## Что проверено в каждом релизе

1. Установка полного ZIP, версия, совпадение каждого файла с архивом.
2. Немедленное изменение Surface; восстановление вручную испорченного value param; отсутствие контроля после выключения PBR2GTA.
3. Разрешение справки для каждого шейдера фактического каталога Sollumz.
4. Превью PNG → DDS.
5. Экспорт YDR и YDD: два Drawable в словаре, общий материал, отдельный материал скрытого LOW LOD, выключенный материал с собственными значениями.
6. Смена выделения на другой объект во время worker: экспортируется исходный ассет, новое выделение сохраняется.
7. Восстановление Preferences и выделения, в том числе при искусственной ошибке синхронного повторного запуска.
8. В 2.8+ — настройки custom-режима, намеренно отличающиеся от Preferences; экспорт Native/XML для GEN8/GEN9. Legacy XML проверен в релизах, где есть отдельный legacy-оператор.
9. Обратное чтение XML и Native: числовые значения SpecularFresnel сверены с Surface и сохранённым значением выключенного материала.
10. YTD и DDS при выключенной PBR-конвертации; Specular/Gloss; оружейный shader с palette.
11. Реальные DDS-заголовки: BC1, BC3, BC5U — 512 × 512, восемь уровней, последний 4 × 4. Palette — RGBA8, один уровень. У оружейного specular сохранён его штатный BC1-профиль.
12. Видимая ошибка при удалении обязательного узла; Undo/Redo; сохранение и повторное открытие временной сцены с дальнейшим изменением Surface.

## Сбои промежуточных прогонов

Прогоны действительно обнаружили и помогли исправить подмену состава выделения в 2.8.3/2.9.0, перенос служебных RNA-полей из плоского оператора и некорректное определение старой структуры справочника 2.7.

Отдельный краш Blender 4.5 возник в тестовом завершении: `wm_exit_schedule_delayed → WM_event_add_ui_handler → BLI_addhead`, при попытке закрыть Blender в том же callback, который только что выполнил `open_mainfile`. Тест теперь возвращает управление Blender после загрузки и завершает процесс на следующем проходе. Это исправление тестового запуска, не подмена исправления экспортера. Финальные прогоны всех сред завершились с кодом 0.

Локальные подробные логи и временные ассеты: `build/compat-matrix/<version>/`. Старые неудачные результаты сохранены там как `result-*-previous.json`; финальные доказательства вынесены в каталог отчёта.

## Новые версии Sollumz

В рабочем адаптере нет условий вида «если версия 2.8.0». При сохранении возможностей API новая версия использует тот же путь. Для проверки следующего релиза предусмотрено:

```powershell
python scripts/check_sollumz_releases.py --prepare --run
```

Команда обновляет список официальных стабильных релизов от 2.7, скачивает их ZIP, готовит отдельные зависимости и прогоняет установленную сборку. Тестовые пути Blender можно передать через `--blender-old` и `--blender`. Это повторяемая локальная проверка, не настроенное расписание.

Будущая смена API или требований к Blender всё ещё может потребовать доработки; будущие версии нельзя считать проверенными заранее. Совместимость с Sollumz не означает совместимость любой его зависимости с любой версией Python: в частности, исходный PyMateria 0.1.0 из Sollumz 2.8.0 не загружается корректно в ранее проверенном Blender 5.2/Python 3.13. Поэтому официальную 2.8.0 здесь проверяли с её рабочей средой Blender 4.5/Python 3.11.

Прогон проверяет заявленные сценарии, а не все возможные сцены, GPU и комбинации шейдеров. Визуальное совпадение с GTA и работа игровых серверов этим отчётом не измерялись.
